## 3. Temuan KRITIS

### <a id="sec-01"></a>SEC-01 · Service account Google + private key di workspace `api/`

- **Severity:** KRITIS — **Aplikasi:** api / cross-cutting
- **Lokasi:** [api/gen-lang-client-0965506946-e8ecd1f5cf1b.json](../api/gen-lang-client-0965506946-e8ecd1f5cf1b.json)
- **Bukti:** File JSON `"type": "service_account"` dengan `private_key` PEM utuh + `client_email`. Diacu oleh `api/.env.local` via `GOOGLE_SERVICE_ACCOUNT_JSON_PATH`.
- **Dampak:** Siapa pun dengan akses disk/workspace bisa impersonate service account dan memanggil API Google (Calendar, Sheets, dll.) — biaya, kuota, dan data terdampak.
- **Status git:** Tidak ter-track (di-ignore via `api/.gitignore`). **Tapi tetap di disk produksi/dev.**
- **Rekomendasi:**
  1. Revoke key di Google Cloud Console **sekarang**.
  2. Generate key baru, simpan di luar webroot (`/etc/secrets/` di Hostinger atau env raw).
  3. Set `GOOGLE_SERVICE_ACCOUNT_JSON_PATH` ke path baru; hapus file dari `api/`.
  4. Audit `git log --all -- '*.json'` untuk memastikan tidak pernah ter-commit.

### <a id="sec-02"></a>SEC-02 · OAuth client secret Google di root workspace

- **Severity:** KRITIS — **Aplikasi:** cross-cutting
- **Lokasi:** [client_secret_877479939791-dajbuljfuhjrtaugs2srvk3q9gnbdaug.apps.googleusercontent.com.json](../client_secret_877479939791-dajbuljfuhjrtaugs2srvk3q9gnbdaug.apps.googleusercontent.com.json)

- **Rekomendasi:** Rotate client secret di Google Console; hapus file; simpan kredensial OAuth hanya di env server / Google Secret Manager.

### <a id="sec-03"></a>SEC-03 · `deploy/api2.env` ter-track git berisi DB_PASS, JWT_SECRET, VAPID keys

- **Severity:** KRITIS — **Aplikasi:** cross-cutting
- **Lokasi:** [deploy/api2.env](../deploy/api2.env)
- **Bukti:** `git ls-files` menemukan file. Isi mengandung `DB_PASS`, `JWT_SECRET` 64-hex, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`.
- **Dampak:** Siapa pun yang clone repo (atau kontributor lama) dapat:
  - Memalsukan JWT staging → akses semua endpoint terlindungi.
  - Kirim push notification atas nama aplikasi.
  - Bila DB staging accessible dari publik → kompromi total.
- **Rekomendasi:**
  1. `git rm --cached deploy/api2.env`, tambahkan `deploy/*.env` ke `.gitignore`.
  2. Rotate **semua** secret di file ini (DB, JWT, VAPID).
  3. Pertimbangkan `git filter-repo` untuk menghapus dari history (penting bila repo pernah publik atau diakses orang yang tidak lagi berhak).
  4. Sediakan `deploy/api2.env.example` dengan placeholder saja.

### <a id="sec-04"></a>SEC-04 · Dump SQL ~89 MB ter-track git

### <a id="sec-06"></a>SEC-06 · `GET /api/print` tanpa AuthMiddleware (IDOR data kwitansi)

- **Severity:** KRITIS — **Aplikasi:** api
- **Lokasi:** [api/routes/02_auth_v2_profil.php:65](../api/routes/02_auth_v2_profil.php)
- **Bukti:**

```65:65:api/routes/02_auth_v2_profil.php
    $app->get('/api/print', [PrintController::class, 'getPrintData']);
```

  Tidak ada `->add(new AuthMiddleware())`. Controller (`PrintController::getPrintData`) secara eksplisit mendokumentasikan "sengaja tanpa auth".
- **Dampak:** Siapa pun dengan `id_santri`/NIS bisa GET `/api/print?id_santri=...&page=uwaba&tahun_ajaran=...` dan menerima biodata santri + rincian pembayaran lengkap (uwaba / khusus / PSB / tunggakan). NIS adalah angka 7 digit yang mudah di-enumerate.
- **Rekomendasi:**
  - **Minimal:** Tambah `AuthMiddleware` + otorisasi (santri hanya boleh akses dirinya, staff sesuai role).
  - **Lebih baik:** Signed URL sekali pakai dengan expiry (pola `PublicPaymentTokenHelper`).
  - Tetap pertahankan kompatibilitas: terbitkan token print dari halaman terotentikasi.

### <a id="sec-07"></a>SEC-07 · JWT & refresh token disimpan di `localStorage` (rentan XSS)

- **Severity:** KRITIS — **Aplikasi:** ebeddien, mybeddien
- **Lokasi:**
  - [ebeddien/src/store/authStore.js:135-146](../ebeddien/src/store/authStore.js)
  - [mybeddien/src/store/authStore.js:24-44](../mybeddien/src/store/authStore.js)
  - [ebeddien/src/services/api.js](../ebeddien/src/services/api.js) (interceptor baca `auth_token`)
- **Bukti:**

```135:140:ebeddien/src/store/authStore.js
    localStorage.setItem('auth_token', token)
```

```24:28:mybeddien/src/store/authStore.js
    localStorage.setItem('auth_token', token)
```

- **Dampak:** Skrip XSS apa pun (dependency rusak, CDN tercemar, ekstensi browser jahat) bisa eksfiltrasi bearer token → akses penuh API sebagai user. Tidak ada isolasi `HttpOnly`.
- **Rekomendasi:**
  1. **Idealnya:** httpOnly + Secure + SameSite cookie dari backend; frontend cukup `withCredentials`.
  2. **Sementara:** sessionStorage + rotate token pendek (≤ 15 menit) + refresh berbasis cookie httpOnly.
  3. Harden CSP (lepas `'unsafe-inline'` — lihat [SEC-23](#sec-23)).
  4. Audit ulang seluruh dependency (`npm audit`, `npm dedupe`).

## 4. Temuan TINGGI

### Backend `api`

#### <a id="sec-08"></a>SEC-08 · IDOR biodata santri publik membocorkan NIK, ortu, alamat, WA

- **Severity:** TINGGI — **Aplikasi:** api
- **Lokasi:** [api/src/Controllers/SantriController.php:786-809](../api/src/Controllers/SantriController.php) (`getPublicSantri`), route di [api/routes/03_public.php:46](../api/routes/03_public.php)
- **Bukti:** Query memilih `s.nik`, kolom orang tua, `no_telpon`, `email`, `alamat`. Endpoint publik, hanya butuh `id` (NIS atau ID internal).
- **Dampak:** IDOR privasi; enumerasi NIS 7 digit memungkinkan scrap massal data orang tua + nomor WA → target phishing/penipuan.
- **Rekomendasi:**
  - Minimalkan field publik (hanya `nama`, `nis`, status, foto opsional).
  - Wajibkan token signed atau OTP wali untuk field sensitif.
  - Rate limit ketat khusus `/api/public/santri`.

### Frontend `ebeddien` (performa)

#### <a id="perf-03"></a>PERF-03 · Chunk `sheet-vendor` ~2,1 MB di bundle ebeddien

- **Severity:** TINGGI — **Aplikasi:** ebeddien
